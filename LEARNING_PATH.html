Layer Its job What it must never do
Object language Represent values and perform logic, arithmetic, recursion, algorithms, tag checks, and error propagation using pure untyped lambda terms. Ask Racket to decide or compute an object-language result.
Sugar Mechanically expand def, _let, _if, and _cons into names, nested lambdas, and applications. Add a computational primitive or host-language branch.
Lazy Racket host Load terms and supply the non-strict evaluation strategy required by the direct Y combinator. Replace lambda-encoded data or control flow.
Readers and tests Force, render, and compare an already-computed encoding at the one-way observation boundary. Feed rendered strings, numbers, or host decisions back into object-language computation.

00 Prove the sugar is only notation What is object language, what is syntax, and what is observation? Root Bitter ⌄

Establish trust in the notation before complexity arrives. The root route is readable because four macros translate directly into names, lambdas, and applications; the bitter/ route exposes selected expansions.

Read in this order

  1. def: curried-looking arguments become nested one-argument lambdas.
  2. _let: local binding becomes immediate lambda application.
  3. _if: an encoded Boolean selects a branch.
  4. _cons: syntax expands into repeated encoded pair construction.

Compare directly

Put true, false, and _and from the root and bitter logic files side by side. One is comfortable notation; the other makes the nested lambdas visible.

macros/macros.rkt logic.rkt bitter/logic.rkt
The encoded Boolean chooses the branch. Racket's macro never decides which object-language result wins.

Ready to move on?

Explain why _if adds notation but no computational power.

Next: logic is selection →
01 Logic is selection How can choosing one of two arguments encode truth and control flow? Root Bitter ⌄

A Boolean contains no host Boolean. It accepts two alternatives and returns one. Every connective is an arrangement of those choices, and the same selector behavior will later project pairs, store signs, and discriminate Option and Result.

Read in this order

  1. true and false
  2. _cond and _not
  3. _and and _or
  4. xor, nor, and nand
  5. b-read, but only as an observer

Trace

Reduce ((_and true) false) only far enough to show which alternatives are selected. Do not translate the terms to Racket #t, #f, or if.

logic.rkt tests/logic-test.rkt
Focused evidence
./run-all-tests.sh tests/logic-test.rkt

Ready to move on?

Explain Boolean meaning entirely as argument selection.

Next: number is repetition →
02 A natural number is repetition How can repeated application stand in for stored numeric data? RootBitter ⌄

A Church numeral is the instruction “apply this function n times.” Addition composes iteration, multiplication repeats addition, and exponentiation repeats multiplication.

Read in conceptual groups

  1. zero, succ, and the small constants
  2. add, mult, and _exp
  3. pred and sub
  4. isZero, then gte, lte, eq, gt, and lt

Notice the untyped lesson

zero is defined as false. The same term acts as zero when given a step and seed, and as false when given two alternatives. Meaning comes from use.

church.rkt bitter/church.rkt tests/church-test.rkt
Focused evidence
./run-all-tests.sh tests/church-test.rkt

Ready to move on?

Explain ((add two) three) as iteration composition, then explain why raw subtraction saturates at zero.

Next: recursion is a fixed point →
03 Recursion is a fixed point How can self-application provide recursion without a host-language loop? RootBitter ⌄

Y gives a helper access to its own fixed point, so recursion arrives as an argument rather than a reference to the helper's Racket name. Lazy evaluation delays the self-application long enough for an encoded base case to select a result.

Read in this order

  1. Y
  2. fact and fact-helper
  3. fib and fib-helper
  4. nSum and nSum-helper

Why Lazy Racket matters

In an eager host, direct self-application expands before a base case can prevent it. Here, promises let the lambda-encoded predicate decide whether recursion is demanded.

Next: data is selection →
04 Data is a protocol of selectors How can the same choice mechanism encode pairs, lists, and traversal? RootBitter ⌄

pair stores two values by waiting for a selector. head applies true, and tail applies false. A list is a chain of those pairs ending in nil.

Read in this order

  1. pair and nil in core.rkt
  2. head, tail, onelist, twolist
  3. len, isNil, and ind
  4. app, rev, _map, _filter, and both folds
  5. take, insert, replace, drop, and remove

What converges here

Boolean choice projects the pair, Church naturals count and index, and Y traverses a chain whose length was not known in advance.

Focused evidence
./run-all-tests.sh tests/lists-test.rkt

Ready to move on?

Explain one step of _map as a new pair plus a recursive continuation.

Next: division and partiality →
05 Division exposes domains and partiality What happens when an object-language function has no result for a demanded input? RootBitter ⌄

Division searches for a quotient using lambda-encoded comparison, multiplication, conditionals, and fixed-point recursion. This is where “outside the mathematical domain” must be separated from “the host throws an exception.”

Read in this order

  1. div and div-helper
  2. div-n-mod
  3. mod
  4. isEven and isOdd

Partial means no result

Raw Church-natural division by zero does not return an error. Demanding the result continues evaluating. Other representations and wrappers deliberately choose other policies.

division.rkt bitter/division.rkt tests/division-test.rkt README · complete policy table
Focused terminating cases
./run-all-tests.sh tests/division-test.rkt
Do not probe a known partial zero-divisor expression interactively and leave it running. The repository's dedicated nontermination suite uses disposable subprocesses and explicit deadlines.

Ready to move on?

Next: compose a numeric tower →
06 Build a numeric tower by composition How do Booleans, naturals, pairs, and recursion become integers and rationals? RootBitter ⌄

Integers are encoded as {sign Boolean, Church-natural magnitude}. Rationals compose again as {signed numerator, Church-natural denominator}. The capability comes from representation and reuse, not a new primitive.

Integers first

  1. makeZ, constants, and z-read
  2. addZ, especially mixed signs
  3. inversion, subtraction, multiplication, division, exponentiation
  4. zero, comparisons, absolute value, and parity

Then rationals

  1. constructors and selectors
  2. euclidean, _lcm, and reduce
  3. reciprocal, sign inversion, and arithmetic
  4. comparisons and floorR
Representation policy is now visible: positive and negative integer zero compare equal, and the raw rational family treats a zero numerator or denominator as rational zero.

Next: algorithms reappear →
07 Ordinary algorithms reappear When does programming inside lambda calculus begin to feel ordinary again? RootBitter ⌄

Once the library has data, arithmetic, comparison, branching, and recursion, familiar algorithm design returns without changing the computational substrate.

Search

binarySearch and binarySearchZ combine sorted lists, half-open bounds, indexing, comparison, division, and recursion. The raw result is {found Boolean, Church-natural index}.

Sorting

bubble-sort, insertion-sort, and selection-sort reconstruct textbook algorithms with immutable list replacement, lambda-encoded counters, and fixed-point helpers.

Focused search evidence
./run-all-tests.sh tests/algorithms-test.rkt
The focused suite currently exercises both binary-search families. The three sorting implementations exist in algorithms.rkt but currently have no automated assertions, so their source and comments are the evidence available for that part of this stop.

Ready to move on?

For one search step, identify the bound calculation, lookup, comparison, and recursive branch. For one sorting pass, identify list replacement standing in for mutation.

Next: upgrade the representation →
08 Change the representation, keep the language What does a binary representation upgrade buy without adding computational power? Root ⌄

Church naturals are unary: cost grows with the represented value. Binary naturals are most-significant-bit-first lambda-encoded lists of Church zero/one digits, so representation grows with bit length.

Read in this order

  1. binary-lists.rkt: bits, carry, borrow, normalization, long division, gcd/lcm, parity, exponentiation
  2. int-binary-lists.rkt: the existing sign-plus-magnitude shape over binary magnitude
  3. binary-rationals.rkt: the existing rational shape lifted onto binary operations

What changes

Cost changes. Purity and expressive power do not. The signed and rational layers preserve their higher-level shapes while swapping the arithmetic underneath.

Next: build runtime discipline →
09 Build runtime discipline inside the untyped world Can untyped terms validate tags, propagate errors, and represent absence themselves? Strict ⌄

This is runtime-tagged untyped lambda calculus, not a static type system. Validation decisions and returned errors come from encoded tags, pairs, predicates, and conditionals.

Begin with TYPES.rkt

  1. make-obj, type, and val
  2. Church-numeral tags for error, Boolean, natural, integer, list, rational, Option, and Result
  3. constructors, predicates, and error values
  4. type-check*, fully-type*, and keep-typed3
  5. make-some/NONE and make-ok/make-err-result
  6. read-any as the observation boundary

Then revisit familiar domains

  1. LOGIC.rkt and CHURCH.rkt
  2. RECURSION.rkt and INTEGERS.rkt
  3. LISTS.rkt, especially IND-OPT
  4. ALGORITHMS.rkt: search becomes Option
  5. RATIONALS.rkt: DIVr returns Result
Host strings are opaque diagnostic payloads. Object-language control flow branches on lambda-encoded structure, never on the contents of those strings.

Next: compare coercion →
10 Compare rejection with coercion What changes when a mismatched tagged value is converted instead of rejected? Coercive ⌄

The conversion families define policy; the COERCE-* wrappers apply that policy before invoking an existing raw operation. Read this as a controlled comparison with strict rejection, not as a universal meaning for every raw value.

Read in this order

  1. types/coercive/TYPES.rkt
  2. conversion families such as bool-to-nat and list-to-bool
  3. COERCE-1, COERCE-2, and the mixed-conversion wrappers
  4. sample coercive logic, natural, integer, list, and rational modules

A concrete contrast

Strict ADD(TRUE)(FIVE) produces ADD(arg1(err:nat)). Coercive ADD(TRUE)(FIVE) converts TRUE to natural one and produces nat:6.

Repository vocabulary

Name the exact layer.

Raw
An unwrapped lambda encoding such as true, five, posTwo, or a root list.
Typed
Usually a raw value wrapped in a lambda-encoded runtime tag. It does not mean statically typed lambda calculus.
Church natural
A unary iterator encoding. A binary natural is instead a lambda-encoded list of Church-zero/Church-one digits.
Integer and rational markers
Raw integer names use Z, tagged wrappers use z; raw rationals use R, tagged wrappers use r.
Binary-backed
Names ending in -bin use the scalable binary digit-list representation.
Curried call
((add two) three) means add takes one argument and returns a function waiting for the next.
Partial
Some demanded inputs do not produce a value. This does not mean “returns an error” unless the layer explicitly says so.
Reader
A one-way host observer that renders an already-computed encoding. Its host result never steers object-language computation.

The finish line

Tell the story, not just the feature list.

Selection gives behavior. Behavior gives representation. Reusable representations give algorithms. A representation change gives scale. Those same untyped pieces can even describe and enforce their own runtime discipline.

Once you can explain that accumulation, use ROADMAP.md for a different purpose: implementation history, settled decisions, and possible future work.
